Comprehensive AgriCrate Overview

The Pitch & Grounding

AgriCrate (meaning "bridge" in Hindi) gives a farmer personalized crop and health advisory — by text or photo, in their own language — built from real satellite, soil, and weather data instead of guesswork. The system adapts dynamically globally, specifically demonstrating cross-border capabilities between India and Brazil.

India Context: The project targets the Build with AI: Digital India Agritech hackathon. While the challenge mentions "inspired by India AgriN", the real AgriN focuses on genetic resources. AgriCrate is genuinely inspired by the India Network on Digital Agriculture (coordinated by IIT Delhi) which focuses on AI, geospatial tech, and data-driven solutions.

System Architecture & Layering

The architecture is comprised of four main layers driving the Zero Cost infrastructure:

  • Data Sources: Satellite NDVI (Google Earth Engine Sentinel-2 via noncommercial registration), Soil Properties (SoilGrids via GEE community catalog), Weather & Forecast (Open-Meteo API), and Historical Crop Context (FAOSTAT API).
  • Ingestion / Fusion (Country Adapter): Abstracted data fetchers to handle any global coordinate transparently.
  • AI Core: Gemini API via Google AI Studio (not Vertex AI). This handles all multimodal inputs (images for crop disease) and text translation entirely within the prompt, preventing the need for separate GCP services.
  • Delivery & Interface: A farmer app (Leaflet.js + OpenStreetMap) and a policymaker dashboard powered by Postgres materialized views.

Full Tech Stack

  • Frontend: Next.js 16.3 (App Router), React 19, Tailwind CSS v4, Framer Motion, Zustand. Hosted on Vercel/Netlify.
  • Backend: Supabase Postgres (free tier limits 500MB), Supabase Auth (handles roles), Supabase Storage (1GB for crop photos), and Supabase Edge Functions (Deno runtime for lightweight serverless logic).

Postgres Data Model & Security

AgriCrate stores profiles, fields, health profiles, advisories, and diagnoses. A critical component is the Row Level Security (RLS) policy:

create policy "farmers see own fields" on fields for select using (auth.uid() = owner_id);

This ensures complete privacy. For policymakers, we avoid BigQuery by creating a Postgres materialized view (`regional_trends`) that aggregates data (NDVI, requests) per country and region. Policymakers only see this aggregated view, acting as our Digital Public Good (DPG) "do-no-harm" privacy layer.

Critical Constraints & Maintenance

Because the app relies on Supabase's free tier, projects pause after 7 days of inactivity. To ensure the live link remains active for judges up to Demo Day, a keep-alive ping (cron job via cron-job.org or GitHub Actions) must be maintained to hit the API every 3–4 days.

Also, API keys must be loaded via server-side Environment Variables to prevent Gemini quota theft.

Digital Public Good (DPG) Compliance

The project is fully open-source (MIT/Apache 2.0). It aligns directly with SDG 2 (Zero Hunger) and SDG 13 (Climate Action). All farmer data is protected via RLS, preventing data exploitation.
